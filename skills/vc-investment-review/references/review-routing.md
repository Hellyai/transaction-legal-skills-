# 审阅路由与身份识别（详细规则）

## 一、审阅场景识别

### 1. TS / Term Sheet
- 默认深度：**快速完整性审核**。
- 目标：在最短篇幅内确认 TS 是否"能签""该补什么"。
- 仅在用户明确要求"深度审核"时展开逐条法律分析。
- 审核重点清单见 `ts-review.md`。

### 2. 投资协议 / 增资协议 / 股权转让协议
- 重点审：交易执行、交割安排、Cap Table、尽调风险落实、违约责任、解除、
  多投资人是否互不承担连带责任。
- 不默认展开股东权利深度分析（那是股东协议的事）；但投资协议中若已含投资人权利
  条款，需与该轮股东协议核对一致。

### 3. 股东协议
- 重点审：投资人权利是否齐备，以及每项权利条款是否投资人友好。
- 权利清单与 Key Terms 输出见 `shareholder-agreement-review.md`。

### 4. 交割文件最终核验
- **仅在以下条件之一满足时启用**，否则不要默认展开：
  - 用户提供了章程、股东会决议、董事会决议、披露函、放弃函；或
  - 用户明确说"交割前审核 / 签署前审核 / 打款前审核"。
- 核验口径见 `closing-final-check.md`。

## 二、我方身份识别

依以下顺序判断并选择对应审阅重点（可叠加，例如"既有投资人 + 政府引导基金"）：

### 1. 新进投资人
必须加载 `new-investor-review.md`，系统核查：

- 本轮文件矩阵及协议、章程、Cap Table、披露与附属文件关系；
- 投资主体—证券—权利映射；
- 估值、金额、单价、股比、ESOP和完全摊薄口径；
- 交割条件、付款、长停日、解除和交割后义务；
- 尽调风险是否通过交割前提、陈述保证、特别赔偿或投后义务闭环；
- 回购、清算、反稀释、MFN、共同出售、拖售等经济权利；
- 董事、观察员、否决权、信息权等治理权；
- 与领投方、其他新投资人及现存投资人的权利差异；
- 创始人及公司责任限制、责任财产和救济可执行性；
- 签署、付款和交割前必须完成的谈判、决策及资料事项。

### 2. 既有投资人
额外重点：
- 必须先加载 `existing-investor-review.md`，建立文件版本矩阵和主体—轮次—股权批次映射；
- 未完成上述两项底稿时，对回购、MFN、反稀释、清算顺位等仅输出条件性结论；
- 上一轮投后义务是否履行；
- 上一轮违约责任是否被豁免 / 过度豁免；
- 既有回购、反稀释、优先认购、优先购买、共同出售、MFN、董事席位、
  保护性条款、信息权是否被削弱、推迟或放弃；
- 新老投资人权益是否实质一致；
- 必须同步生成一份"与上轮投资协议、股东协议的修改要点总结及指定方权益影响分析"；
- 专项分析至少覆盖：是否新增/发放/扩容 ESOP，指定方过往参与过几轮投资，各轮投资金额、投资单价或估值、
  取得股比及本轮后持股变化；
- 专项分析必须判断权利是否平等：本轮是否新增仅由新投资人享有的特殊权利、优惠待遇、优先顺位或更强行权机制，
  而指定方未同步享有，或指定方同类权利更弱、门槛更高、顺位更后、期限更短；
- 专项分析必须核查"本轮协议替代/终止前序轮协议"风险：本轮协议是否通过完整协议、取代前约定、
  终止原协议、重述协议、各方确认无其他权利义务等条款，使前序轮投资协议/股东协议项下权利、已触发救济、
  违约责任或索赔权失效。

若缺少上轮文件或历史 Cap Table，应在输出中列明"无法判断项"，并提示需补充：
上轮投资协议、上轮股东协议、上轮章程/补充协议、历轮 Cap Table、工商登记资料、ESOP 决议或激励计划文件。

### 通用 Cap Table 强制路由

任一文件或附件包含 Excel Cap Table、ESOP、估值、注册资本、投资单价、持股比例、完全稀释股本或反稀释计算时，必须调用 `captable` skill。法律审阅引用专项核验结果；未完成时标注“待 Cap Table 核验”。

### 3. 政府引导基金 / 地方产业基金
额外关注：
- 落地、返投、地方基金考核；
- 落地主体设立；
- 税收 / 就业 / 研发 / 生产或运营承诺及未完成后果。

### 4. 其他产业投资人
结合自身战略诉求（业务协同、供应链、董事观察、信息权等）调整审阅重点。

### 身份不明时的处理
若从文件与对话中无法判断身份，**先向用户确认身份再展开**，不要假设。

## 三、身份 × 场景 组合速查

| 场景 \ 身份 | 新进 | 既有 | 政府引导/地方产业基金 |
|---|---|---|---|
| TS | 估值/股比/交割条件/权利骨架 | 同左 + 不削弱既有权利 | 同左 + 返投落地体现 |
| 投资协议 | 文件与交易结构/主体证券/Cap Table/交割/尽调闭环/责任救济 | 上一轮义务履行/违约豁免/连带 + 上轮投资协议修改要点对比 | 返投承诺与落地主体 |
| 股东协议 | 经济权利/治理权/退出/投资人分层/可执行性 | 逐项比对是否削弱 + 上轮股东协议修改要点对比 | 返投相关权利/承诺 |
| 交割核验 | 横向一致/签署齐备 | 既有权利未被夹带放弃 | 落地返投义务落实 |

## 四、新进投资人成果交付路由

新进投资人审阅应输出一份系统化综合意见，包含：本轮文件矩阵、投资主体—证券—权利映射、交易经济、Cap Table、交割与尽调闭环、经济权利、治理权、投资人分层、责任救济及执行清单。

用户要求 Word 成果时，在本轮协议目录下新建 `【项目名-协议名-YYYYMMDD】` 独立审阅文件夹，默认文件名为 `【项目名-新进投资人协议审阅意见-YYYYMMDD】.docx`。如提供同一协议不同版本并要求比较，再输出相应对比稿。不得修改、移动或覆盖原始文件。

## 五、既有投资人成果交付路由

当用户身份为既有投资人，且提供本轮与上轮投资协议/股东协议时，除聊天内结构化审阅意见外，应同步准备：
- 一份综合审阅意见：包含核心结论、P0/P1/P2、处理标签、实质修改、指定方影响及建议；
- 每类协议一份对比稿：以本轮文件与上一轮有效文件为基础，尽量逐字展示新增、删除、修改内容；若技术上无法生成原生修订模式，
  应输出 Word 版逐条对比表并说明限制。

在本轮协议目录下新建 `【项目名-协议名-YYYYMMDD】` 独立审阅文件夹，不修改、移动或覆盖原始文件。使用命名：`【项目名-协议审阅意见-YYYYMMDD】.docx`、`【项目名-投资协议-上轮对比稿-YYYYMMDD】.docx`、`【项目名-股东协议-上轮对比稿-YYYYMMDD】.docx`。
